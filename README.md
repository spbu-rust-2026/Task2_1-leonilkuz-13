# Метонимия

Жила-была грустная строка `MATMEX LUCHSHE VSEH`. Ей казалось, что её никто не замечает, поэтому она попросила первое слово представлять всю компанию. «Я — вся строка!» — гордо объявило `MATMEX`. Так и получилась метонимия: часть текста выступает от имени целого (литераторы могут уточнить термин после решения).

Строка приободрилась и попросила добавить ей в конец `!`. Но Rust попытался одновременно держать первое слово за рукав и перекраивать всю строку. На сцену вышел borrow checker: «Либо держим слово, либо меняем строку!» Помогите героям договориться: функция `process` должна дописать `!` и вернуть срез первого слова, которое было в строке до изменения, а программа — скомпилироваться.

## Задача

Исправьте функцию `process`, чтобы она дописывала к строке `!` и возвращала срез её первого слова **до изменения строки**. Если в строке нет слов, верните пустой срез. Сигнатуру функции менять нельзя. Программа должна компилироваться: убедите borrow checker, что строку и её срез можно обработать без конфликта. Клонировать всю строку «на всякий случай» не считается убедительным аргументом.

## Примеры

| Строка до вызова | Строка после вызова | Возвращённое слово |
|---|---|---|
| `MATMEX LUCHSHE VSEH` | `MATMEX LUCHSHE VSEH!` | `MATMEX` |
| `Rust спасает дедлайн` | `Rust спасает дедлайн!` | `Rust` |
| `одинокое` | `одинокое!` | `одинокое` |

Возвращается первое слово исходной строки: добавленный `!` в него не входит.

<summary>Памятка по Git</summary>

Перед работой проверьте, где вы и что изменилось:

```bash
git status
git diff
```

Сохраните только нужные файлы и проверьте, что попадёт в коммит:

```bash
git add README.md src/main.rs
git diff --cached
git commit -m "Fix borrow checker in Task2_1"
git push
```

Если `git status` показывает неожиданные файлы, не добавляйте всё подряд через `git add .`: сначала разберитесь, откуда они взялись. Особенно подозрительны `target/` и случайно сохранённые секреты. Коммит без проверки — это как дать borrow checker'у `&mut` на продакшен.
